## Patterns Applied

- **Verification before exposure**: untrusted bytes stay in staging; exact size/CID, catalog commit, and backend eligibility precede registry/provider visibility.
- **Names are mutable; CIDs are bytes**: signed expiring alias records map names to exact content; provider claims and loaded-capability advertisements remain separate.
- **One workload-neutral network substrate**: blob and live-job streams are bounded opaque Phase transports; LUCID owns model/Ollama semantics.
- **Idle starts after open**: transport lock/multistream/open negotiation has a dedicated bounded deadline; request idle timeout governs established-stream silence.
- **Evidence is not proof**: reputation is local, privacy-minimal, decayed, inspectable, and never described as global correctness. Redundant literal commitment comparison is bounded and does not identify the dishonest peer.
- **Backend differences stay at the adapter boundary**: MLX reuses `Worker`, router, policy, commitments, receipts, identity, registry, and HTTP surfaces instead of creating a parallel stack.
- **Unsupported means fail closed**: MLX hardware/runtime status remains explicitly unverified; non-Apple configuration fails before filesystem or network activity.
- **Evidence-bearing automation**: validation binds command results to source fingerprint, lock hash, host OS/architecture, toolchain, durations, and logs under ignored `target/` storage.

## Integration Points

- `ollama.rs` calls `ContentPlane::pull` → signed alias resolution → signed provider selection → `phase-net` blob stream → artifact-store staged verification/commit → registry/catalog publication.
- `router.rs` prefers `Discovery::open_job_relay_stream` → ordered `JobEvent` frames → HTTP stream → exact delivered-output commitment → terminal signed receipt verification.
- `main.rs` constructs one `Discovery` swarm with peer/infrastructure roles and wires the same identity through worker receipts, DHT records, relay authentication, content records, and local evidence.
- `EvidenceRuntime` observes classified router outcomes; routing consults assessment only after exact content, capability, policy, and reachability gates.
- `MlxWorker` and `LlamaCppWorker` implement the same Phase `Worker` contract and are consumed by the existing router/API.
- `phase-validate.sh linux` is the UMBP/Scratch native gate: offline locked release build, workspace tests, and strict Clippy.

## Architectural Decisions

Accepted in `decisions.md` on 2026-08-09:

- Content identity, signed alias/provider records, and verification-before-exposure.
- Live relay v2 with opaque bounded substreams and distinct negotiation/idle timing.
- Explicit infrastructure reachability roles; rendezvous assists discovery but never authorizes.
- Reputation as private local evidence; bounded literal redundancy without correctness overclaim.
- MLX as a pinned local subprocess adapter with explicit unverified hardware status.
