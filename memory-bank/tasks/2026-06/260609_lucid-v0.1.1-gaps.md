## Patterns Applied

- **Embeddings ride the existing commitment/receipt machinery.** A worker emits one
  `OutputChunk { kind: "embedding", data: serde_json::to_vec(&Vec<f32>), seq }` per input; the
  HTTP collector decodes + orders by `seq`. No new `JobResult` shape, and the SEC-05
  `verify_peer_receipt` path covers embedding relays unchanged. See `decisions.md` 2026-06-09.
- **Self-traffic vs donation-protection split.** `should_serve_self` honors only `manual_pause`;
  battery/thermal/time/concurrency/allowlist remain on the inbound-relay (`should_serve`) path.
  See `decisions.md` 2026-06-09.
- **Pull stub = register-already-present, not download.** `/api/pull` advertises a local GGUF
  (llama-cpp mode) or no-ops to success (echo mode); name hygiene mirrors
  `worker_llama::resolve_model_path`. Network pull + real content CIDs is v0.2.

## Post-merge validation + follow-up fixes (2026-06-09)

After PR #10 merged, validated on real infra and ran the authz demo — which surfaced two
latent bugs (fixed in follow-up branch `lucid-sec05-receipt-binding`) and one deferred:

- **Validated on `scratch`** (ARM64, cargo 1.96.0): build + 87 tests + live `/api/embed`,
  `/api/embeddings`, `/api/pull` over HTTP against the echo worker (deterministic 16-dim vectors,
  `x-lucid-routed-via: local`).
- **Deployed to the umbp relay**: cross-compiled the x86_64 binary (Docker `--platform linux/amd64
  rust:1.96-bookworm` into `target-linux-amd64/`; `cross` 0.2.5 was broken by the local rustup
  install), peer-id-preserving `lucidd-relay.service` swap. Peer-id
  `12D3KooWJ6vTjo6yFgEc…` preserved, `:4001` live, old binary backed up at `~/bin/lucidd.pre-v0.1.1`.
  NOTE: a `--mode relay` node exercises none of the v0.1.1 worker/API paths — this was hygiene
  (foundation node on latest `main`) + x86_64 build proof, not a new live capability.
- **Two-node authz demo** (`scratch`, two echo nodes): default-deny **rejected** an unauthorized
  routed job (`peer refused: submitter not authorized`); flipping `allow_unauthenticated_jobs = true`
  + SIGHUP made the same job **accepted**, routed to the peer (`x-lucid-routed-via: peer:…`), and
  returned with `x-lucid-receipt-verified: true`.

**Follow-up fixes (made to enable the demo, both genuine bugs):**
1. **Echo model was undiscoverable cross-peer.** `main.rs` advertised it under `ModelCid([0u8;32])`
   while every name→CID resolver uses `ModelCid::from_model_id(...)`. A consume-only node could
   never find an echo peer. Fixed to `from_model_id("echo")`.
2. **Peer receipts never bound (SEC-05).** Both workers were constructed with a *random* identity
   (`EchoWorker::new()` / `NodeIdentity::generate()`), so `verify_peer_receipt`'s
   `worker_pubkey → delivering PeerId` bind always failed — `x-lucid-receipt-verified` could never be
   `true` for a peer-served job. Fixed so both workers sign with the node identity (`node_identity`).
   See `decisions.md` 2026-06-09.

**Deferred (latent bug, NOT fixed):** the policy notify-watcher watches the config file's *parent
directory*, so any file change there (e.g. a co-located log) triggers a reload feedback loop
(observed 387k reloads/6s when a log shared the policy dir). Harmless in production (policy lives in
`~/.config/lucidd`, logs go to journald) — but the watcher should scope to the file, not the dir.
Tracked for a future fix.
