Security & Trust Model

Default-deny networking, loopback lockdown, and honest limits.

Every claim on this page is traced directly to enforcement in the Rust and Tauri source code. Where a guarantee does not exist yet, it is stated plainly below.

Local machine & browser protection

  • Loopback-only HTTP bind: lucidd refuses any non-loopback LUCIDD_HOST (only 127.0.0.1 and ::1 are permitted).
  • DNS-rebinding Host guard: Every HTTP request is checked by middleware that returns 403 Forbidden on missing, duplicated, or non-loopback Host headers or URI authorities.
  • Private control API bearer token: All /api/lucid/* endpoints require Authorization: Bearer <64-hex> verified in constant time and return Cache-Control: no-store. In LUCID Desktop, the per-session token (0600) never enters the Svelte WebView—only Rust Tauri commands hold it.
  • Explicit permission gates: Turning on GPU sharing (/api/lucid/provide) or downloading/pinning the runtime (/api/lucid/runtime/setup) requires confirm_permission: true (else 428 Precondition Required). LUCID Desktop refuses to run as root (uid == 0).
  • Folder & runtime confinement: Model folder validation blocks symlinks, relative paths, system roots, $HOME root, and sensitive folders (.ssh, .gnupg, .aws, .kube, .docker, Keychains, .config/phase). Downloaded llama.cpp b12651 archives and auto-managed ggml-rpc-server binaries are verified against pinned SHA-256 digests before extraction and before every spawn.
  • Worker subprocess isolation: Each llama-server spawn gets a cleared environment, a fresh 256-bit OS CSPRNG LLAMA_API_KEY (never in argv), --cors-origins localhost --no-cors-credentials --no-webui --no-slots, and strict no-proxy / no-redirect loopback HTTP clients.
  • Cross-tenant KV-cache isolation: llama-server runs with --no-cache-prompt --cache-ram 0 --cache-reuse 0 and server-owned cache_prompt: false on every request so one caller cannot probe another caller's prompt prefix via timing.

Network, identity & peer authorization

  • Ed25519 root identity: Persistent 32-byte key stored atomically at mode 0600 inside a 0700 directory (phase-identity). The same key derives your libp2p PeerId.
  • Encrypted transport: All libp2p traffic runs over Noise XX (TCP & Circuit Relay v2) or TLS 1.3 (QUIC v1).
  • Default-deny job execution: policy.toml starts with authorized_submitters = [] and allow_unauthenticated_jobs = false. Inbound jobs must pass SignedManifest::verify_for_remote_execution() (15-minute max TTL, 5-minute max clock skew), bind signer_pubkey to the delivering libp2p PeerId, and match an allowlisted key or active circle enrollment grant.
  • Strictest gate for GPU pooling (/phase/shard-rpc/1.0.0): A synchronous peer filter drops non-enrolled peers before reading a single byte, never honors allow_unauthenticated_jobs, requires live cluster_enabled = true and !manual_pause, and re-checks authorization every 250 ms—tearing down live tunnels immediately on opt-out or revocation.
  • Memory safety: All library crates and LUCID Desktop's Rust backend enforce #![deny(unsafe_code)] (zero unsafe blocks in workspace crates; third-party crypto/network crates are audited via cargo audit and cargo deny in CI).

What is NOT protected yet (honest limits)

Do not rely on LUCID for guarantees it has not built yet:

  • Prompt visibility on the serving peer: Noise and QUIC protect prompts from relays and network observers, not from the peer executing your inference. Use X-Lucid-Local-Only: true (or the Desktop Local Only toggle) for prompts that must stay on your own device.
  • Receipts prove attribution, not hidden compute: A verified SignedReceipt proves which peer signed the exact tokens you received. Redundant spot-checking (remote-spot-checked) adds local deterministic consistency evidence, not a cryptographic proof that the peer used a specific model weight or quantization.
  • Tier-1 GPU pooling carries SSH-equivalent peer trust: Enabling cluster_enabled exposes a loopback ggml-rpc-server to your explicitly enrolled circle over /phase/shard-rpc/1.0.0. Use Tier-1 sharding only among machines you personally own or trust at the OS level. Tier-2 UntrustedSpotChecked sharding is fail-closed and not implemented.
  • No built-in Tor / SOCKS5 transport yet: Peers and relays see direct IP addresses unless you route through an OS-level Tor gateway (see TailsOS & Tor guide, including same-LAN RFC 1918 caveats).
  • DNS bootstrap without DNSSEC: TXT lookups on bootstrap.phasebased.net pin each relay's PeerId (preventing key impersonation), but do not enforce DNSSEC; pass explicit --no-default-bootstrap --relay-peer <multiaddr> for maximum bootstrap certainty.
  • Whole-file blob verification: /phase/blob/1.0.0 enforces sequential offsets and commits only after full-file SHA-256 verification, but does not yet verify per-chunk Merkle proofs (a corrupt chunk from a bad provider triggers a clean restart from offset 0 on failover).
  • In-memory job replay cache: Inbound job replay protection is process-local (bounded by the 15-minute manifest TTL), and ContentProviderRecord rollback tracking is in-memory (whereas AliasRecord replay protection persists atomically at mode 0600).

Reporting a vulnerability

Please report security issues privately through GitHub's Security Advisories page on msitarzewski/phase rather than opening a public issue. Include reproduction steps, affected crate or binary version, and impact.
